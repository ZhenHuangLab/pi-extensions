## 剩余工作

- **阶段 6 效果评估：** 与 Pi 默认压缩和只清理的插件对照，统计多次任务的通过率、总费用、延迟，
  以及清理后不久又被召回的结果比例，用 `claude-haiku-5-5` 实验。完成条件是这些数据支持清理参数的默认值：
  0.5T 触发点、0.1T 释放下限、保留 8 次调用和 1 KB 最小清理大小。召回比例高时先调整 K 和
  触发点的默认值；仍不够时，再为非 Anthropic 通道评估分类模型。
- **`openai-responses` 真实验证：** 需要 OpenAI API key 或 “Sign in with ChatGPT” 登录。目前只有本地
  模拟服务验证。
- **Responses 窗口中的图片和开发者消息：** 图片目前使本次压缩改用文本摘要，开发者消息不作为明文保留，
  多代理项没有覆盖。需要按服务端的实际行为确定保留规则和预算。
- **实际服务端清理、召回和缓存重写：** 在足够长的 Anthropic 任务中实际触发 `applied_edits`，测量每次
  清理后缓存从哪里开始重写、多久重写一次，并观察真实模型的召回行为。缓存数据用于确定清理触发点。
  非 Anthropic 通道的本地清理也还没有在真实任务中触发。
- **摘要质量：** 原生摘要和回退摘要在长任务中保留目标、约束、决定和精确标识的程度。现有标识读回
  只证明窗口可读。
- **Responses 通道的后台压缩：** Codex 官方客户端已加入后台压缩（见[架构](architecture.md#72-openai-responses)
  和[参考资料](references.md#codex-后台压缩)），v0.1.0 只做同步压缩。设想如下：上下文超过阈值 T 的某个比例后，
  对当时捕获的前缀发出 trigger 请求，结果只保存在内存中；在之后的某个 `turn_end` 把它作为压缩草案采用，
  保留后缀是捕获点之后追加的全部内容；捕获之后分支或模型发生变化，或出现任何 `context_edit` 或压缩条目时，
  丢弃该结果。启用前先用模拟服务和一次真实检查验证。

## 验证纪律

连续压缩时，被替换的覆盖范围和保留后缀必须恰好包含每个来源条目一次。覆盖完整工具批次，
并验证自动/手动压缩同时触发，以及响应完成后、提交前发生取消或分支/模型切换的情况。
失效候选不得产生压缩条目，也不得发起回退请求。

直接拼接原生块的回放和 HTTP 字段断言不证明 Pi checkpoint 或重启恢复。这类结论必须通过 Pi
重建的真实请求，并比较保留的序列化消息和覆盖范围，不能只检查回复中是否还有某个标识符。
空工具定义的比较不能代替非空工具及工具结果的验证。

本地检查使用真实 Pi 会话机制，配合合成 provider 或本地模拟服务。真实接口检查显式启用，并只发送
合成内容。不保存认证信息、签名、encrypted state 或 thinking 文本到公开日志。

每次记录命令、依赖版本、实际通道、通过范围和未通过项。新增断言之后，旧运行日志仍只证明旧断言。
只有新改动、失败或未解决的具体问题才触发重跑，不重复消耗真实模型请求来获取相同结论。
